# Needs
- Reduce retained browser memory, DOM nodes, and event listeners during replay usage, based on the new manual perf smoke evidence.
- Keep replay behavior, controls, camera/focus modes, timeline, stage overlays, and report/replay navigation unchanged for players.
- Clean up obviously shipped build-output hygiene issues if confirmed by perf:bundle, especially accidental non-runtime artifacts in apps/web/dist.
- Reduce the most expensive image payloads only where measurement shows meaningful savings and the UI does not visually regress.
- Keep API/simulation optimization as a measured watchpoint rather than a first implementation target unless new evidence contradicts the current perf:api results.
- Use the manual perf tools for before/after evidence; do not add CI gates or blocking perf budgets yet.

# Context
- This request follows the manual profiling tool pass. The app now has npm run perf:browser, perf:replay, perf:compare, perf:bundle, and perf:api. These tools are intentionally manual and must remain outside CI for this request.
- The strongest signal is replay retention: replay stress grows heap, DOM nodes, and listeners more than the normal GP loop while network transfer stays flat. Inspect cleanup and retention in ReplayView, useReplayClock, ReplayStageOverlay, and CircuitMap first.
- Likely replay remediation areas: requestAnimationFrame cancellation, setTimeout cleanup, speed/focus menu listeners, SVG connector/marker retention, animation/camera state held after replay restart or control toggles, and duplicate DOM generated by repeated replay interactions.
- Do not weaken replay UX to improve metrics. The replay must still render map, cars, director beats, start/finish presentation, weather/timeline, focus driver, speed controls, restart, pause/play, and Back to stand.
- Bundle evidence is secondary but actionable. perf:bundle reports image weight dominates. Also verify whether apps/web/dist contains non-runtime artifacts (for example tsbuildinfo, test JS, maps, or source TS) because those should not ship if served by production.
- The existing draft request req_124 covers eager bundle trimming and script/document boundaries. Avoid duplicating req_124; this corpus should either consume its findings as context or leave broad code-splitting to that request. This request may fix dist hygiene if it is small and directly confirmed.
- API evidence does not justify first-pass optimization: race simulation is low milliseconds and no database path is involved in perf:api. Preserve the API payload watchpoint, especially replayTrace/result JSON size, but do not spend effort there before replay retention.

# Acceptance criteria
- AC1: A before/after perf:replay run with at least 10 cycles shows reduced retained heap, DOM node, and/or listener growth versus the recorded baseline, and perf:compare marks the after run as better or stable for the targeted metrics.
- AC2: Replay controls and flows remain functionally intact: pause/play, restart, speed selection, focus driver, map/cars, weather/timeline, race director overlays, report access, and Back to stand still work.
- AC3: The implementation includes the smallest necessary cleanup fixes for replay timers/listeners/animation state; any persistent growth that remains is documented with a clear suspected owner.
- AC4: perf:bundle is rerun after changes. If non-runtime artifacts are present in apps/web/dist, they are removed from the production output or explicitly documented if they are local-only artifacts not served in production.
- AC5: At least the largest image payloads are reviewed. Any converted/resized asset has before/after size evidence and no broken image requests in representative app flows.
- AC6: API/simulation perf remains a watchpoint only unless perf:api regresses; no API contract or race result payload shape changes without separate product approval.
- AC7: npm run typecheck, npm run lint, npm test, npm run build, npm run test:e2e -- --project=chromium, npm run perf:replay -- --cycles 10, npm run perf:bundle, and npm run logics:validate pass or have documented non-blocking perf evidence where applicable.
